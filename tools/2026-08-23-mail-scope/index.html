邮件解剖台

把一封 .eml 拖进来。验 DKIM 签名、拆 MIME 结构、还原被编码的中文与附件名、逐条列出钓鱼信号 —— 全部在你自己的浏览器里算完，邮件一个字节都不上传。

RSA 验签在页内手写 RFC 5322 / 2045 / 2047 / 2231 / 6376 零上传 · 零依赖

拖入 .eml / .msg 原文 / 任意原始邮件文本，或者粘贴到下面

在 Gmail 里是「下载邮件」,Outlook 是「另存为 .eml」,Apple Mail 是「显示原文」。

先拿示例试试

六封构造好的邮件，覆盖从「一切正常」到「所有钓鱼手法叠在一起」。其中两封由 openssl 用同一把演示密钥真实签名 —— 页面里的验签结果是当场算出来的，不是写死的。

它做什么。信头按 RFC 5322 展开折行与解析结构化字段；被 RFC 2047 编码的主题与显示名、被 RFC 2231 拆成多段的附件名都会还原；MIME 树按 RFC 2045/2046 逐层拆开，base64 / quoted-printable / uuencode 解码后再按声明的字符集转成可读文本。DKIM 走 RFC 6376 的 simple 与 relaxed 两套规范化，正文摘要与抬头摘要都在页内算，RSA-PKCS#1 v1.5 验签也是页内手写的大整数模幂 —— 把 DNS 里的 p= 贴进来就能当场验完。

它不做什么。不查 DNS（纯前端没有这个能力），所以 SPF 的 a / mx / include 机制会如实标注「需要 DNS」，只有 ip4 / ip6 是离线可判的；不做 Ed25519 的 DKIM(RFC 8463)；不解密 S/MIME 与 PGP。

隐私。没有任何网络请求 —— 邮件、附件、你贴进来的公钥全部只存在这个标签页里。正文预览跑在无脚本的沙箱 iframe 中，远程图片一律拦下，所以打开可疑邮件不会向对方回报「你已读」。

示例里出现的域名全部来自 RFC 2606 / RFC 5737 保留段（example / 198.51.100.0/24 / 203.0.113.0/24），演示用的 RSA 密钥对是构建时现生成的，不对应任何真实服务。
