    它能做什么、不能做什么

    读得懂的容器

    经典 pcap（大端 / 小端 × 微秒 / 纳秒 四种魔数都认）与 pcapng（多 Section、多接口、if_tsresol 时间精度、Enhanced / Simple Packet Block）。链路层支持以太网 II（含 802.1Q / QinQ 多层 VLAN 标签）、Linux cooked v1 / v2、Raw IP、NULL / Loopback。

    拆得开的协议

    IPv4（选项、分片标志）、IPv6（逐跳 / 路由 / 目的选项 / 分片扩展首部）、ARP、ICMP（含差错报文里内嵌的原始报文）、ICMPv6（回显、邻居发现）、TCP（全部标志位 + MSS / 窗口缩放 / SACK / 时间戳选项）、UDP、DNS（含压缩指针，A / AAAA / CNAME / MX / TXT / NS / PTR / SOA / SRV）、HTTP/1.x（请求行、状态行、首部、主体长度）、TLS（记录层，ClientHello / ServerHello 的版本、密码套件、SNI、ALPN、supported_versions）、NTP、QUIC（仅识别长短首部）。

    算得出的东西

    五元组会话表（双向包数 / 字节数 / 时长 / 速率）、TCP 三次握手与 RTT、重传 / 重复 ACK / 序号跳跃 / 零窗口 / RST 判定、按序号去重叠的双向流重组、协议层次、端点统计、按时间分桶的吞吐曲线。

    做不到的

    • 不能抓包——浏览器碰不到网卡。抓包请用 tcpdump -i any -w a.pcap 或 Wireshark，然后把文件拖进来。
    • 不解密 TLS——没有密钥就没有明文，只能看到记录层与握手里的明文字段（SNI、ALPN、密码套件）。
    • 不重组 IP 分片——非首片会如实标成「分片数据」，不会拼起来再解上层。
    • HTTP 只按 TCP 段的边界识别，不做跨段的 chunked 解码；HTTP/2 与 QUIC 内层不解。
    • 单个文件解析上限 6 万个包，超过的部分会明确提示，而不是悄悄丢掉。

    过滤器语法

    != 在多值字段上按「所有取值都不等」判定（例如 tcp.port != 443 会排除任一端是 443 的包），这和某些抓包工具的「任一取值不等」不同，这里选了更符合直觉的那个。

    怎么验的

    抓包文件全程留在浏览器里：解析、过滤、重组、导出都由本页的 JavaScript 完成，没有任何上传。旗标与备注按文件内容指纹存在 localStorage，换一台机器就没有了。
