为什么这一页存在

高斯模糊是一次线性、可逆性很强的运算:原始像素还在,只是被摊开了。知道模糊半径,就能用 Richardson–Lucy 迭代把它逼回来。马赛克和色块不一样 —— 一整格只剩一个均值,信息是真的被丢掉了。

说句公道话:σ 拉得越大,这套朴素反卷积能逼回来的越少(σ=4 时差距缩小五成上下,σ=12 时只剩一成半)。但原始像素始终还在文件里,换个更强的先验(比如已知这是一串数字)就能接着挖 —— 所以别把身家押在模糊上。

Richardson–Lucy 迭代:反复「假设一个清晰图 → 按同样的核糊一遍 → 和手上这张比 → 按比值修正」。

色块

唯一无条件安全的做法。整块像素被替换成一个颜色,原信息不存在于文件里,也就没有还原可言。

马赛克

格子够大就安全:一格只剩一个均值。格子小于字高的一半时,笔画轮廓会残留,配合字典穷举有被猜出的先例。

模糊

不推荐。它是线性运算,原始信息只是被摊开;知道核的形状就能反卷积。左边那一页就是现场演示。

裁掉

比什么都强:不需要出现在图里的东西,一开始就别截进来。

检测是怎么做的

没有用任何 OCR —— 这个工具不认字,它只找「哪里像文字」:

  • 先转灰度,再算 Sobel 梯度幅值 |Gx|+|Gy|。文字的笔画边缘梯度密集,大片纯色背景接近 0,所以深色底白字和浅色底黑字一视同仁。
  • 用大津法在梯度直方图上自动定阈值,二值化成笔画掩膜。
  • 8 邻接连通域标记(两遍扫描 + 并查集)把掩膜切成一个个连通块,再按高度、宽高比、填充率把分隔线、面板边框、噪点滤掉。
  • 按垂直重叠把连通块聚成「行」,行内按水平间隙切成「词块」:间隙大于 2.4 倍字高的算换了一段(比如左右分栏),大于 0.62 倍字高的算换了一个词。

这四步的每一个算子都和 scipy.ndimage 的对应实现做过随机对拍(高斯 200 组、均值 200 组、Sobel 200 组、连通域 200 组、大津 200 组,逐值一致),所以「框画在哪」是可复现的,不是玄学。

「够不够安全」是怎么判的

判据只有一条:遮挡块要大到能把一个字压进一格以内。工具会取遮挡区域里检测到的中位字高 h,然后:

  • 马赛克格子 ≥ 0.9h → 安全;≥ 0.45h → 偏弱;更小 → 危险。
  • 模糊无论 σ 多大都不会评「安全」,最高只到「偏弱」。
  • 色块 → 安全。
现实里的教训:2016 年前后多起「马赛克被逆推」的案例,以及浏览器里常见的「毛玻璃遮挡」,都是栽在遮挡强度不足 —— 而不是栽在算法本身有后门。

导出的时候发生了什么

  • 脱敏是直接改像素再导出的,导出的 PNG/JPEG 里没有任何一份原始像素,也没有图层信息 —— 拿到文件的人无从「关掉图层」。
  • Canvas 导出天然不带 EXIF:原图里的 GPS、机型、拍摄时间在这一步就没了。
  • 如果你只是想留个可继续编辑的版本,用「导出标注 JSON」—— 那份 JSON 里只有图形坐标,不含图片。

隐私

图片从 <input type="file">、拖放或剪贴板进来之后,始终只存在于这一页的内存与 canvas 里。没有任何网络请求,也没有把图片写进 localStorage —— 关掉标签页就什么都不剩。只有界面上的参数(颜色、格子大小、衬底设置)会记在本地,方便下次打开还是你顺手的那套。
