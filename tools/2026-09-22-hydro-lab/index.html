这玩意儿是怎么算的

整页只有一个 HTML 文件，水力内核是照着 OWA EPANET 2.3 的 C 源码逐行改写的 JavaScript，内部单位与它完全一致（流量 cfs、水头 ft），所以每个系数都能指回源码的具体一行。

求解器

  • 全局梯度法（Todini & Pilati）：每一轮把非线性水头损失线性化成对称正定方程组，解出节点水头后再回代修正管段流量。对应 hydsolver.c 的 hydsolve() / newflows()。
  • 稀疏求解：按最小度重排 + 符号分解 + 数值 LDLT，和 EPANET 的 smatrix.c 同一路数；上千节点的管网也能在几十毫秒内解完。
  • 水头损失：Hazen-Williams（R = 4.727·L / C1.852 / d4.871）、Darcy-Weisbach（Re≤2000 走 Hagen-Poiseuille，Re≥4000 走 Swamee-Jain 显式近似 Colebrook-White，中间 2000–4000 走 Dunlop 过渡多项式）、Chezy-Manning。局部损失统一折算成 Q² 基准。
  • 低流量处理：水力坡降小于 RQtol 时改用线性关系，避免 q→0 时梯度趋零把牛顿步顶飞 —— 这一段的常数与 EPANET 逐位相同。
  • 状态判定：止回阀反流关断、水泵超关死点扬程、满池不许进水/空池不许出水、PRV/PSV/FCV 的六态切换，全部按 hydstatus.c 的规则逐条实现。
  • 延时模拟：用水模式、水池水位积分、按水位/时刻/时钟触发的简单控制、时间步自适应收缩（正好停在水池灌满、控制触发、模式换段那一刻），对应 hydraul.c 的 timestep() 一族。

数值口径（对结果有影响的地方，逐条写明）

  • 只做需水量驱动分析（DDA）：认为节点无论压力多低都能取到设定水量，所以负压会如实显示成负数，不会自动削减用水量。EPANET 2.2 起的压力驱动分析（PDA）本工具不支持，遇到 Demand Model PDA 会明确提示。
  • 不支持 [RULES] 基于规则的控制（只执行 [CONTROLS] 简单控制），文件里有规则时会提示被忽略。
  • 不做水质/水龄模拟；[QUALITY]、[REACTIONS]、[SOURCES]、[MIXING] 段会被跳过。
  • EPANET 把 ACCURACY 夹在 [1e-5, 1e-1] 之间（input3.c 的 optionvalue），本工具照夹，所以填更小的值不会更准。
  • 报表口径与 EPANET 工具箱一致：关闭的管段流量/流速/水损一律报 0；水泵没有流速；水泵的「水损」是带号的进出口水头差（负值即扬程）。
  • 「千米水损」= 水头损失 ÷ 管长 × 1000，只对有长度的管道有意义，水泵阀门不算。

对拍

交付前用两套彼此独立的实现逐点对过。

两个 oracle 之间本身也有差异：WNTR 把 |Q| < 4×10⁻⁴ m³/s 的 Hazen-Williams 水损换成三次样条平滑，EPANET 走的是另一套低流量线性化，于是它们在细管上彼此就差 2.6×10⁻⁵ m³/s —— 而本引擎与 EPANET 的差是 10⁻⁹ 量级。所以对 WNTR 的判据是「差得不比两个 oracle 彼此差得多」。

怎么用得顺手

  • 先在「管网」页拖用水量倍率，看哪个节点最先掉到红线以下 —— 这是判断「还能接多少新用户」最快的办法。
  • 点中一条管，在右栏直接改管径/粗糙系数，全网瞬间重算；觉得不对就「还原改动」。
  • 「校核」页的消防流量扫描会把每个节点在当前时刻的可供火灾流量全算一遍，直接指出消防最薄弱的片区。
  • 改完的管网可以「导出当前管网为 INP」，拿回 EPANET 桌面版继续做。

改动与判据会存在本机 localStorage；地址栏里的分享码带着「用哪个示例 + 改了哪些参数」，可以直接发给同事。自定义粘贴的 INP 太大，不进分享码，只存本机。

水力内核逐条对照 OWA EPANET 2.3 源码（hydcoeffs.c / hydsolver.c / hydstatus.c / hydraul.c）实现，交付前用官方引擎逐节点、逐管段、逐时刻对拍。
