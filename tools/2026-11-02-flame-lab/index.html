    怎么拿到 profile

    Go
    go test -cpuprofile cpu.pb.gz，或 curl -o cpu.pb.gz :6060/debug/pprof/profile?seconds=30
    Linux perf
    perf record -F 99 -g -p PID 之后 perf script > out.perf
    Node
    node --cpu-prof app.js 生成 .cpuprofile
    Chrome
    开发者工具 → 性能 → 录制 → 保存 profile（trace JSON）
    Python
    py-spy record --format raw -o out.folded -- python app.py
    Java
    async-profiler -o collapsed

    数字是怎么算的

    • 自身：样本的最内层（叶子）是这个函数的那部分；总计：调用栈里出现过这个函数的样本，同一个样本里递归出现多次只算一次（与 pprof 的 flat / cum 相同）。
    • 聚焦 / 忽略 / 隐藏照 pprof 的 -focus / -ignore / -hide：匹配函数名、文件名或映射文件；同时命中聚焦与忽略的按忽略处理；帧全部被隐藏的样本整条丢掉。
    • 搜索的占比 = 至少含一个命中帧的样本量（与 flamegraph.pl 的 Matched 相同，嵌套命中不重复算）。
    • 差分照 difffolded.pl + flamegraph.pl：宽度取「新」，颜色取该帧自身的变化；归一化时基线每条栈按 int(旧 × 新总量 ÷ 旧总量) 缩放。
    • perf script 折叠照 stackcollapse-perf.pl：默认按第一种事件过滤、进程名作根帧、去掉 +0x 偏移与参数表；最后一个样本后面要有空行才算。
    • cpuprofile 的时间：每个样本的时长 = 下一个样本的时间戳 − 它自己的，最后一个到 endTime 为止；时间戳倒退时先按时间排序（与 DevTools 一致）。

    隐私与存储

    解析、绘图都在这个页面里完成，没有任何网络请求。资料库存在本机浏览器的 localStorage（约 5 MB 上限），存的是解析后的调用栈，不是原文件；pprof 只保存函数粒度。

    内置示例都是真实录制：Go 1.25 订单服务（优化前 / 后各跑 3 秒，GOMAXPROCS=1 GOGC=400，macOS）、Node 25 静态博客生成器、Python 3.14 日志统计流水线（ITIMER_PROF 每 1 ms 采一次）。
