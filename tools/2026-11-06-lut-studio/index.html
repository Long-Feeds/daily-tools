RGB Slope Offset Power

公式（ASC CDL v1.2）：out = clamp(in × slope + offset)power，再按 Rec.709 亮度做饱和度。色轮把圆盘位置换成「亮度为 0」的 RGB 偏移，方向与矢量示波器一致：往红色推就加红。

曲线 单调三次插值（PCHIP），不会过冲

斜率按 Fritsch–Butland 调和平均取，与 scipy 的 PchipInterpolator 逐点一致；控制点之间曲线不会超出相邻点的范围，所以不会出现「拉一个点，别处翻起来」。

HSL 八色 在 OKLCh 里按色相分区

八个锚点取 sRGB 的红、橙、黄、绿、青、蓝、紫、洋红在 OKLCh 里的色相；相邻锚点之间用余弦过渡，权重之和恒为 1，所以不会有断层。低饱和像素（灰、白）的色相与明度改动按饱和度渐弱，避免灰阶被染色。

      处理顺序与口径

      1. 输入变换（仅 Log 素材）：厂商 Log 解码 → 摄影机色域到 Rec.709 的 3×3 矩阵 → Narkowicz 2015 ACES 拟合影调曲线 → sRGB 编码。
      2. 导入的 LUT（位置选「调色前」时）。
      3. 配色：Reinhard / MKL / 直方图匹配（统计量在源图与参考图各取最多 65 536 个等距采样像素上算；源图某个通道几乎没有方差时——比如黑白照片的 α/β——该通道只平移均值、不缩放，MKL 对应方向按伪逆处理）。
      4. 线性光：sRGB 解码 → 曝光（×2EV）→ 白平衡（Krystek 1985 普朗克轨迹 + Duv，Bradford 色适应）→ 黑白通道混合 → 编码 → 高光滚降。
      5. 影调：白 / 黑色阶 → 对比度（以 18% 灰为枢轴的 C¹ 连续 S 曲线）→ 高光 / 阴影（按 Rec.709 亮度做比例增益，滑块全程单调）。
      6. ASC CDL（色轮）→ 曲线（RGB 主曲线后接单通道）→ HSL 八色（OKLCh）→ 饱和度 / 自然饱和度。
      7. 导入的 LUT（位置选「调色后」时）→ 整体强度（与第 1 步输出混合）→ 截到 [0, 1]。

      预览不是另一套算法：每次参数变化都会把上面整条管线烘成 33³ LUT，再用四面体插值套到预览上；导出的文件与预览出自同一个网格。拖动滑块时临时用 17³，松手后补成目标网格。

      文件格式

      格式读写说明
      .cube（Adobe / Resolve）✓✓LUT_3D_SIZE / LUT_1D_SIZE、DOMAIN_MIN / MAX、Resolve 的 LUT_1D/3D_INPUT_RANGE 与「1D 整形 + 3D」组合；红色变化最快。
      .3dl（Flame / Lustre）✓✓首行 10 位输入网格，数据为整数；蓝色变化最快。输出位深按 Lustre 头声明，否则按数据最大值推断（≤1023 → 10 位，≤4095 → 12 位，其余 16 位）。
      Hald CLUT（PNG）✓✓等级 L：L² 点网格、边长 L³ 像素，像素顺序与 ImageMagick / ffmpeg haldclut 一致。
      ASC CDL（.cc / .cdl）✓✓只含色轮这一段（Slope / Offset / Power / Saturation），其余调整无法用 CDL 表达。
