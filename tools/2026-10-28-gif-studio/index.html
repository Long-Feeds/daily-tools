      它在做什么

      流水线

      • 抽帧：视频按「源时刻 = 起点 + k × 速度 / 帧率」逐帧定位后画到画布；动图按每帧延迟排出时间轴再取帧。裁剪、缩放、字幕在这一步完成。
      • 量化：统计全片（或每帧）颜色。不同颜色不超过上限时直接用原色，无损；否则用 Wu 方差最小切分（默认）、Heckbert 中位切分或八叉树，可再跑几轮 k-means。
      • 抖动：Floyd–Steinberg 蛇形扫描、Atkinson 误差扩散，或 Bayer 8×8 有序抖动。误差扩散每帧噪点不同，会拖累帧间优化；有序抖动随坐标固定，更适合动画。
      • 帧间优化：每个像素和「上次编码它时的源色」比，差距在容差内就算没变（不会慢慢漂移）。只编码变化框，框内没变的像素写透明下标，LZW 遇到成片透明压得极狠；整帧没变就并进上一帧的延迟。
      • 封装：GIF 用自写的变长 LZW（2–12 位，满表发清除码）；APNG 用浏览器自带的 deflate；动画 WebP 每帧交给浏览器的 WebP 编码器，再由本页按 RIFF 规范拼成 ANMF 帧。

      浏览器怎么播

      • GIF 延迟以 1/100 秒计。延迟 ≤ 1（10 ms）的帧，Chrome / Firefox / Safari 都按 100 ms 播放，所以本页最短写 2（每秒 50 帧），并用误差扩散取整保住总时长。
      • GIF 的循环靠 NETSCAPE2.0 扩展：没有它只播一遍；字段值是「额外重复次数」，0 表示无限。APNG 的 num_plays、WebP 的 loop count 则是「总播放次数」。本页的「播放 N 次」已按各格式换算。
      • 处置方式 2 在浏览器里是「清成透明」，不是背景色。
      • 结果卡里的 PSNR 是拿浏览器自己解出来的帧（WebCodecs ImageDecoder）和原始帧比的；没有这个接口的浏览器改用本页的 GIF 解码器。
